Eigenen Server hostenHost your own server

Der JumpNDodge-Server ist ein kleines Programm ohne Fenster. Er braucht kaum Leistung – ein alter Laptop, ein Raspberry Pi oder ein Heimserver mit CasaOS reichen. Jeder Raum hat Platz für zwei Spieler, ein Server schafft viele Räume gleichzeitig. The JumpNDodge server is a small program without a window. It needs almost no power – an old laptop, a Raspberry Pi or a home server with CasaOS is enough. Each room holds two players, one server handles many rooms at once.

Docker / CasaOS

Der Server läuft im Container rund um die Uhr und startet nach einem Neustart von selbst.The server runs around the clock in a container and starts again after a reboot.

  1. CasaOS

    App-Store → + (oben rechts) → Benutzerdefinierte App installieren → Importieren → diesen Text einfügen → Installieren. server.json liegt danach in /DATA/AppData/jumpndodge-server.App Store → + (top right) → Install a customized app → Import → paste this → Install. server.json is then in /DATA/AppData/jumpndodge-server.

    name: jumpndodge-server
services:
  jumpndodge-server:
    image: ghcr.io/erqf1/jumpndodge-server:latest
    container_name: jumpndodge-server
    restart: unless-stopped
    ports:
      - target: 47800
        published: "47800"
        protocol: udp
    environment:
      JND_SERVER_NAME: "JumpNDodge Server"
      JND_SERVER_MOTD: "Viel Spaß!"
      JND_SERVER_PASSWORD: ""
    volumes:
      - type: bind
        source: /DATA/AppData/jumpndodge-server
        target: /data

  2. Docker (ohne CasaOS)Docker (without CasaOS)

    docker run -d --name jumpndodge-server --restart unless-stopped \
  -p 47800:47800/udp -p 47801:47801/tcp -v jnd-data:/data \
  -e JND_SERVER_NAME="Mein Server" ghcr.io/erqf1/jumpndodge-server:latest

    Aktualisieren musst du nichts: Der Server lädt neue Versionen selbst (siehe Auto-Update). Ein neues Image bekommst du trotzdem jederzeit über docker pull bzw. „Aktualisieren“ in CasaOS.No need to update by hand: the server downloads new versions itself (see auto-update). You can still get a new image any time with docker pull or “Update” in CasaOS.

Ohne Portweiterleitung: Cloudflare TunnelNo port forwarding: Cloudflare Tunnel

Der Server spricht neben UDP auch WebSocket (TCP-Port 47801). Damit läuft er hinter einem Cloudflare Tunnel – auch bei DS-Lite/CGNAT und ohne Freigabe im Router.Besides UDP the server also speaks WebSocket (TCP port 47801). That lets it run behind a Cloudflare Tunnel – even with DS-Lite/CGNAT and without router rules.

  1. Tunnel anlegenCreate a tunnel

    Cloudflare-Dashboard → Zero Trust → Networks → Tunnels → Create a tunnel → Cloudflared. Den angezeigten Token kopieren (geheim halten).Cloudflare dashboard → Zero Trust → Networks → Tunnels → Create a tunnel → Cloudflared. Copy the token shown (keep it secret).

  2. cloudflared neben dem Server startenRun cloudflared next to the server

    In CasaOS/Docker Compose als zweiten Dienst ergänzen und den Token eintragen:Add it as a second service in CasaOS/Docker Compose and fill in the token:

      cloudflared:
    image: cloudflare/cloudflared:latest
    restart: unless-stopped
    command: tunnel --no-autoupdate run
    environment:
      TUNNEL_TOKEN: "dein-token"

  3. Public Hostname

    Im Tunnel unter Public Hostnames z.B. spiel.deine-domain.de → Service HTTP → jumpndodge-server:47801 (Containername; ohne Docker localhost:47801).Under Public Hostnames add e.g. game.your-domain.com → service HTTP → jumpndodge-server:47801 (container name; without Docker localhost:47801).

  4. VerbindenConnect

    Freunde tragen nur den Hostnamen ein, ohne Port. Cloudflare leitet kein UDP weiter – das Spiel merkt das und verbindet sich automatisch über wss://. So läuft auch der offizielle Server play.mert.win.Friends enter just the hostname, without a port. Cloudflare doesn't forward UDP – the game notices and connects over wss:// automatically. The official server play.mert.win works this way too.

Zusätzlich direkt per UDP? Dann Portweiterleitung wie unten und einen eigenen DNS-Namen mit „Nur DNS“ (graue Wolke) – nicht den Tunnel-Namen.Also want direct UDP? Then forward the port as below and use a separate DNS name set to “DNS only” (grey cloud) – not the tunnel name.

Auto-Update

Der Server schaut regelmäßig ins neueste Release, lädt die passende Datei, prüft sie gegen SHA256SUMS.txt und startet neu, sobald niemand verbunden ist – laufende Runden werden nie unterbrochen.The server regularly checks the latest release, downloads the matching file, verifies it against SHA256SUMS.txt and restarts once nobody is connected – running rounds are never interrupted.

1

Windows / Linux / macOS

Die Programmdatei wird ersetzt und mit denselben Einstellungen neu gestartet.The program file is replaced and restarted with the same settings.

2

Docker / CasaOS

Die neue Datei landet in /data/bin. Beim Neustart nimmt der Container die neuere Version – startet sie nicht, läuft die aus dem Image weiter.The new file goes to /data/bin. On restart the container picks the newer version – if it doesn't start, the image version keeps running.

3

AbschaltenTurn off

"auto_update": false in server.json oder JND_SERVER_AUTO_UPDATE=0."auto_update": false in server.json or JND_SERVER_AUTO_UPDATE=0.

3. Portweiterleitung im Router3. Port forwarding in your router

Damit Freunde aus dem Internet deinen Server erreichen, muss der Router Pakete auf UDP-Port 47800 an den Server-Rechner weitergeben.For friends on the internet to reach your server, your router must pass packets on UDP port 47800 to the server machine.

  1. Feste lokale IP für den ServerFixed local IP for the server

    Im Router dem Server-Rechner immer dieselbe IP geben (FRITZ!Box: Heimnetz → Netzwerk → Gerät bearbeiten → „Diesem Netzwerkgerät immer die gleiche IPv4-Adresse zuweisen“).Give the server machine a fixed IP in your router (DHCP reservation).

  2. Freigabe anlegenCreate the forwarding rule

    FRITZ!Box: Internet → Freigaben → Portfreigaben → Gerät für Freigaben hinzufügen → Server-Rechner wählen → Neue Freigabe → Portfreigabe → Protokoll UDP, Port 47800 bis 47800, an Port 47800 → OK.FRITZ!Box: Internet → Permit Access → Port Sharing → add device → new sharing → port sharing → protocol UDP, port 47800 → OK.

    Telekom Speedport: Internet → Portfreischaltung → Neue Regel → Gerät wählen → UDP 47800 → 47800.
    Vodafone Station / andere: meist unter „Port-Weiterleitung“ oder „NAT“: Protokoll UDP, extern 47800, intern 47800, Ziel = IP des Server-Rechners.    Other routers: usually under “Port forwarding”, “Virtual server” or “NAT”: protocol UDP, external 47800, internal 47800, target = IP of the server machine.

  3. Öffentliche Adresse herausfindenFind your public address

    Deine öffentliche IPv4 zeigt z.B. der Router auf der Übersichtsseite. Da sie sich bei vielen Anschlüssen täglich ändert, lohnt sich ein kostenloser DynDNS-Name (FRITZ!Box: MyFRITZ!, sonst z.B. DuckDNS) – dann verbinden sich Freunde einfach mit dein-name.duckdns.org.Your public IPv4 is shown on your router's overview page. It changes often on many connections, so a free dynamic DNS name (e.g. DuckDNS) is handy – friends then connect to your-name.duckdns.org.

Kein eigenes IPv4 (DS-Lite / CGNAT)? Viele Kabel- und Glasfaseranschlüsse teilen sich eine IPv4-Adresse – dann geht Portweiterleitung über IPv4 nicht. Lösungen: beim Anbieter eine „echte“ IPv4 anfragen (oft kostenlos), über IPv6 verbinden ("bind": "::", Freunde brauchen ebenfalls IPv6) oder einen kleinen Mietserver (VPS) nutzen. Am einfachsten: ein Cloudflare Tunnel – der braucht gar keine Portweiterleitung.No public IPv4 (DS-Lite / CGNAT)? Many connections share one IPv4 address, so IPv4 port forwarding won't work. Options: ask your provider for a real IPv4, connect over IPv6 ("bind": "::", friends need IPv6 too) or rent a small VPS. Easiest: a Cloudflare Tunnel – it needs no port forwarding at all.

HilfeHelp

„Server antwortet nicht““Server doesn't respond”

Läuft der Server? Stimmt die Adresse? Im eigenen Netz die lokale IP nehmen, von außen die öffentliche. Ist die Portweiterleitung auf UDP (nicht TCP) gestellt und zeigt sie auf die richtige lokale IP? Blockiert eine Firewall auf dem Server-Rechner?Is the server running? Is the address right? Use the local IP at home and the public one from outside. Is the forwarding set to UDP (not TCP) and pointing to the right local IP? Is a firewall blocking it?

„Andere Version““Other version”

Spiel und Server brauchen dasselbe Netzwerk-Protokoll. Ist es verschieden, sagt das Spiel, ob das Spiel oder der Server zu alt ist. Mit Auto-Update holt sich der Server neue Versionen selbst; sonst Server-Zip neu laden bzw. Docker-Image aktualisieren.Game and server need the same network protocol. If it differs, the game tells you whether the game or the server is too old. With auto-update the server fetches new versions itself; otherwise download the server again or update the Docker image.

Server mit PasswortPassword-protected server

In server.json ein Passwort eintragen. Spieler ohne Passwort werden abgelehnt.Set a password in server.json. Players without it are rejected.
